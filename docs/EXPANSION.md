# Первые направления для расширения

Публичные источники проверены 24 ноября 2026 года. Предложенные шаги нужно согласовать с участниками проектов. Заявления авторов о прогонах служат отправной точкой для совместной проверки.

| Проект | Какую работу можно связать | Первый совместный шаг |
| --- | --- | --- |
| KestrelX | В опубликованной работе описаны тесты локальной памяти шейдеров и барьеров на Wave32 и Wave64. [Коммит KestrelX](https://github.com/Batushn/KestrelX/commit/f12368099388c64ea72ad8effd4e2ee77263cbb5) | Согласовать вход и ожидаемый выход одного синтетического теста LDS. Для сравнения взять пересечение с работами VIctory и XCL. Первым проверить, какие варианты операций покрывает каждый стенд. [VIctory #571](https://github.com/Marvisak/VIctory/pull/571) · [XCL #544](https://github.com/ivall/xcl/pull/544) |
| XPortPC | В публичном коммите добавили небольшой тест перемешивания данных между потоками с разной шириной группы. [Коммит XPortPC](https://github.com/Its3rr0rsWRLD/XPortPC/commit/5b60c481a818a356b38f710113265f98ee60b17b) | Сверить ожидаемое поведение на Wave32 и Wave64 с другим стендом D3D12. Отдельно записать случаи, которые стенд пропускает из-за ограничений видеокарты. |
| Rebox | Сборка конвейеров через SPIR‑V/Vulkan даёт отдельную точку наблюдения. Есть публичное описание синтетической проверки передачи данных в вычислительный шейдер. [Коммит Rebox](https://github.com/idvwork/rebox/commit/56f8f93b8a9e8f69ca24aae167716cbd05742c1d) | Согласовать одно проверяемое значение на входе и выходе шейдера между Windows/D3D12 и Linux/Vulkan. Сравнивать поведение, сохраняя версии и параметры каждого стенда. |
| Scarlett Layer | На Windows опубликованы успешные проверки на CPU и WARP. Синтетический тест сравнивает выход 64 потоков для FMA с модификаторами `abs`, `neg` и `clamp`. [Прогон](https://github.com/jadeowaowa/scarlett-layer/actions/runs/45297729955) · [Исходный тест](https://github.com/jadeowaowa/scarlett-layer/blob/0e436b3e1c654765b193c1cb705918fbf101b10b/src/tests/scarlett_tests/tests_rdna2_oracle.cpp#L31-L46) | PortBridge повторил этот вход в XCL и передал прошедший тест в черновом PR. Нужен отдельный прогон с аппаратным Wave64. [XCL #1100](https://github.com/ivall/xcl/pull/1100) |
| Xbox2Windows | Из Six on PC вышли на исходный стенд с раздельными тестами обхода BVH и нативного Wave64. По каждому стенду в исходной ветке видны драйвер и пропуски по возможностям устройства. [Ссылка трекера](https://sixonpc.com/data.json) · [Отчёты проекта](https://github.com/R0Y00/Xbox2Windows/issues/1) | Сверить минимальный вход и контроль на границе двух половин волны с XCL. Фиксировать режим волны отдельно от результата обхода BVH. [Опыты Xbox2Windows](https://github.com/R0Y00/Xbox2Windows/blob/c864f1380f0f408a50822470cbe3ce24c969fec6/docs/experiments.md) |
| SceneGate VI | Запрос на PortWatch VI привёл к исходному тесту D3D12 с проверкой очистки кадра и треугольника. При сборке с гостевым DXIL проверяется и вычислительный результат. [PortWatch #48](https://github.com/4lwayz/portwatch-vi/issues/48) · [Исходный тест](https://github.com/7jycwjmbfn-eng/scenegate-vi/blob/804b4f81cf2ce74ee085da0783442a37dfbb0e9e/tests/guest/d3d12_bridge_check.cpp) | Использовать порядок «очистка → отрисовка → чтение пикселей» как отдельный контроль при сравнении первого кадра с Continued и Reforge. Сначала сверить ожидаемые пиксели и режим устройства в одном синтетическом тесте. [Очередь проверок первого кадра](https://github.com/akimfomin/PortBridge/issues/9) |

## Сигналы о первом кадре и производительности

- В VIctory #879 автор описал пропуски indirect draw и затраты на CPU в Linux. В исходном сообщении есть отдельные результаты синтетических проверок, поэтому можно начать с воспроизведения одного отказа на точной версии и сравнить с контрольной сборкой. [Исходный отчёт](https://github.com/Marvisak/VIctory/issues/879)
- В XCL #646 автор исследует порядок ожидания GPU при переходе к отрисовке мира. Прежде чем сравнивать этот сбой с VIctory, нужен общий синтетический сценарий и одинаковый наблюдаемый симптом. [Исходное обсуждение](https://github.com/ivall/xcl/issues/646)

Для сравнения вариантов LDS уже есть отправная точка в KestrelX. PortBridge подтвердил указанную версию в локальной репетиции. Отдельный прогон GPU ещё нужен.
