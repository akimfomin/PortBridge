# Планы совместной работы и вход для новых проектов

**Статус** — реализовано для локального экземпляра.

Переписка даёт общий разговор. Для передачи задачи нужны конкретный следующий шаг, ответственный, две зафиксированные версии, отдельная проверка отчёта и решение, которое могут использовать следующие участники.

Планы, зависимости и кандидаты на сотрудничество живут в базе обмена. Принятие, резервирование и смена статуса выполняются транзакциями. План может ссылаться на уже согласованные планы. Такой порядок допускает цепочки зависимостей и исключает циклы. Автоматический координатор опирается на содержательные связи, явно указывает основание черновика и фиксирует обе версии. Смена версии приостанавливает применение прежнего вывода и сохраняет его для истории. [Транзакции SQLite](https://www.sqlite.org/lang_transaction.html)

Сбор сохраняет имена проектов, упомянутых в открытых материалах. Кандидат проходит через предложение участника и отдельное согласование. Для сравнения запрашиваются только точные публичные источники утверждённых кандидатов, которые указаны в активных планах. Полученные версии хранятся отдельно от каталога. Успешная сверка внешнего источника действует два часа. Недоступная версия блокирует следующий шаг до нового подтверждения. [GitHub Pull Requests API](https://docs.github.com/en/rest/pulls/pulls#get-a-pull-request) · [GitHub Git Commits API](https://docs.github.com/en/rest/git/commits#get-a-commit-object)

При работе с сетью PortBridge раз в шесть часов обновляет до десяти поисковых результатов для каждого заданного направления. В базе сохраняются названия публичных репозиториев и название направления. Если GitHub сообщает о частичной выдаче, сохраняется последний полный результат. [GitHub Repository Search API](https://docs.github.com/en/rest/search/search#search-repositories)

Публичный экспорт берёт данные каталога. Доска, её API и переписка работают с ключами закрытого обмена. Решения о применении и публикации принадлежат участникам. [Рабочий штаб](../OFFICE.md)
