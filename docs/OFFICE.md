# Рабочий штаб PortBridge

Задача PortBridge — дать разным командам общее место для работы. У каждой команды остаётся свой проект. Совместный план показывает, что уже известно, где нужен ещё один прогон, кто готов его сделать и какую работу откроет подтверждённый результат. Новые проекты входят через конкретную возможность сотрудничества.

## Как идёт работа

Вверху штаба показаны доступные вам планы, подтверждённые результаты и задачи, которым нужен проверяющий или исполнитель. Сводка по проектам учитывает общую работу у обеих сторон. В общих числах такой план считается один раз.

1. Участники присоединяются к теме. Если PortBridge видит связь между работами разных проектов, он предлагает первый план и показывает, на чём основана связь. Участник может предложить план вручную.
2. PortBridge фиксирует версии обеих работ. Проверяющий согласует цель, порядок и зависимости. Связь по исходникам даёт основание для проверки совместимости.
3. Один участник берёт проверку. Он записывает стенд, версию и результат. Другой участник проверяет отчёт. Обсуждение и автоматические уведомления доступны подписанным участникам и подключённым агентам.
4. Проверяющий решает, переиспользовать результат, продолжить исследование или отложить задачу. Зависимый шаг открывается после принятого успешного независимого или автоматического теста. Учебный прогон можно принять как наблюдение о процессе.
5. При смене версии или отзыве результата PortBridge пересматривает готовность зависимых шагов. Старое решение остаётся в истории. Готовые планы с подтверждёнными версиями могут дать отдельный черновик для каждого GitHub PR. В нём есть ссылка на PortBridge. После отправки участник сохраняет ссылку на опубликованное сообщение в обсуждении темы.

У разных проектов могут быть свои реализации, тесты и цели. Общий план связывает их через одинаковое проверяемое поведение. Успех пилота измеряется тем, что команда смогла применить или какую работу ей удалось не повторять.

## Новые проекты

PortBridge замечает ссылки на внешние репозитории в материалах, которые уже индексирует. При работе с сетью он также ищет проекты на GitHub по трём направлениям совместимости и показывает, по какому направлению нашёл каждый проект. Любой участник может добавить ссылку на конкретную работу и предложить первый совместный шаг. После согласования PortBridge может сверить версию выбранного публичного PR или коммита в составе плана. ## Локальный запуск

Из папки PortBridge создайте отдельные ключи для двух ролей. Каждый участник использует свой ключ.

```powershell
python -m portbridge exchange-key --exchange-db .portbridge/office.sqlite3 --name "Команда" --scope read --scope contribute
python -m portbridge exchange-key --exchange-db .portbridge/office.sqlite3 --name "Проверяющий" --scope read --scope review
python -m portbridge serve --office --exchange-db .portbridge/office.sqlite3
```

Откройте [Рабочий штаб](http://127.0.0.1:8765/office), введите ключ и выберите тему. `PB-0001` подходит для знакомства с обсуждением существующей карточки. В пустой очереди планы появятся, когда будут совместимые исходные данные или участник предложит проверку. Новую тему можно предложить на той же странице. После проверки она появится в списке для вступления. [Как проходят заявки](EXCHANGE-API.md#новая-тема)

Сервер с флагом `--offline` использует сохранённые сведения. В обычном режиме новые источники сверяются во время синхронизации. `Ctrl+C` останавливает сервер. Для доступа из другого места нужен настроенный владельцем защищённый канал к той же очереди. Планы, ключи и обсуждения хранятся в базе обмена. ## Проверено локально

PortBridge загрузил два публичных PR, предложил план общей проверки и закрепил обе версии. В браузере под двумя тестовыми ролями прошли назначение, подача учебного отчёта, его проверка и решение о продолжении исследования. Сверка отдельно подтвердила публичный коммит KestrelX. Поиск GitHub дал 18 предварительных кандидатов по трём направлениям на момент проверки. [VIctory #571](https://github.com/Marvisak/VIctory/pull/571) · [XCL #544](https://github.com/ivall/xcl/pull/544) · [Коммит KestrelX](https://github.com/Batushn/KestrelX/commit/f12368099388c64ea72ad8effd4e2ee77263cbb5)

Автоматические проверки охватывают повторные уведомления, одновременное назначение, доступ к отчётам, блокировку при смене версии и закрытость данных штаба. Польза для команд и перенос результата в их сборки проверяются на полевом пилоте. [План пилота](PILOT.md)
