# Общая переписка и координатор PortBridge

Участники закрытого обмена подписываются на одну задачу со своими ключами. Каждый видит разговор и новые сообщения в общей теме. Второй клиент может ждать изменения в открытом запросе. Если кто-то подтверждает или отзывает отчёт, подписанные клиенты получают событие по той же теме.

## Включение и обычная работа

Владелец запускает обмен и включает автоматического координатора.

```powershell
python -m portbridge serve --offline --exchange-db .portbridge/exchange.sqlite3 --coordinate
```

Подключённый участник задаёт в своём клиенте `PORTBRIDGE_EXCHANGE_TOKEN`. Для переписки требуется ключ с правами `read` и `contribute`. Подписка доступна с правом `read`. Ключ выдаёт владелец обмена. [Настройка ключей](EXCHANGE-API.md#запуск-и-ключи)

```powershell
python -m portbridge.discuss join PB-0001
python -m portbridge.discuss thread PB-0001
python -m portbridge.discuss watch
```

В другом окне участник может отправить сообщение или ответить по номеру сообщения. Пример для учебной темы:

```powershell
python -m portbridge.discuss send PB-0001 "Могу проверить отрисовку на своём стенде."
python -m portbridge.discuss coordination PB-0001
```

После перерыва `watch --after <последний-ID-обновления>` продолжает со следующего события. Вступивший участник видит прежнюю переписку через `thread`, а поток обновлений начинается с момента вступления. Для выхода используйте `leave PB-0001`.

## Что делает сам PortBridge

- Каждые пять секунд он проверяет подключённые темы по локальному каталогу. Режим работает и при запуске `--offline`.
- Если несколько участников обозначили активную работу над одной задачей, он публикует одно уведомление для этого состава участников. Оно предлагает сверить проверки и распределить работу.
- Если в разных проектах виден один и тот же полный идентификатор ревизии, PortBridge сохраняет связь и сообщает о ней в теме. При смене данных он убирает потерявшую подтверждение связь из действующей выдачи и объясняет изменение в обсуждении.
- По каждой действующей связи с PR или Issue он готовит черновик обращения со ссылкой и ревизией. Сопровождающий проверяет текст, решает, требуется ли правка, и выбирает место публикации.

Автор автоматических сообщений отмечен отдельно. Вывод по общей ревизии касается происхождения материалов. Применимость теста определяется версией, конфигурацией и проверкой у принимающей команды.

Одна очередь обслуживает подключённые установки. На разных машинах она требует согласованного владельцем защищённого доступа через локальный порт. Публичный каталог по-прежнему строится из каталога источников и проверенных карточек. Закрытые обсуждения, подписки и черновики доступны через закрытый обмен.
