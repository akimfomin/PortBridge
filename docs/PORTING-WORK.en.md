## Reproduce SceneGate VI pixels

Check out `804b4f81cf2ce74ee085da0783442a37dfbb0e9e`. The original host fixtures use the same 37 × 23 texture, background, overlapping rectangles, and exact RGBA8 expectations. Use a Windows CMake shell with Visual Studio C++ and the Vulkan SDK if following the project's build. [Pinned source and prerequisites](https://github.com/7jycwjmbfn-eng/scenegate-vi/blob/804b4f81cf2ce74ee085da0783442a37dfbb0e9e/README.md#run-the-tests)

```powershell
cmake -S . -B build/pixels -A x64 -DXS_D3D12_WARP_TESTS=ON -DXS_VULKAN=ON
cmake --build build/pixels --config Release --target xscarlet-d3d12-check xscarlet-vk-check
.\build\pixels\Release\xscarlet-d3d12-check.exe
.\build\pixels\Release\xscarlet-d3d12-check.exe --warp
ctest --test-dir build/pixels -C Release -R '^vulkan_readback$' --output-on-failure
```

The recorded host checks built those same executable sources directly with LLVM-MinGW Clang 23.1.6 in C++20 mode and the project's pinned nlohmann JSON 3.11.3. For D3D12, compile `src/tools/d3d12_check.cpp` with `clear_pass.cpp`, `d3d12/device.cpp`, and `d3d12/offscreen.cpp` from `src/backends/graphics`, plus `-DWIN32_LEAN_AND_MEAN -DNOMINMAX -ld3d12 -ld3dcompiler -ldxgi`. For Vulkan, use `src/tools/vulkan_check.cpp`, `clear_pass.cpp`, and `vulkan/offscreen.cpp` with the Vulkan headers and loader. Add `-Isrc` and the JSON include directory to each build. On Windows 11 build 28000, the RTX 4070 Ti SUPER driver 617.14 returned all 851 pixels in each hardware backend. Microsoft Basic Render Driver returned all 851 in WARP. [D3D12 source](https://github.com/7jycwjmbfn-eng/scenegate-vi/blob/804b4f81cf2ce74ee085da0783442a37dfbb0e9e/src/tools/d3d12_check.cpp) · [Vulkan source](https://github.com/7jycwjmbfn-eng/scenegate-vi/blob/804b4f81cf2ce74ee085da0783442a37dfbb0e9e/src/tools/vulkan_check.cpp)

For the triangle control, call `start()` from the unchanged C fixture with the original `readback` and `draw` callbacks exposed through a native DLL as `XsProbeReadback` and `XsProbeDraw`. Each pass checks 64 pixels and varies blue from 63 through 94 across 32 draws. In the deliberately failing run, substitute `d3d12::render` on the same 8 × 8 background for `render_triangle` while keeping the input length guard and copy intact. Normal runs returned `0` three times on each D3D12 adapter. All six controls returned `0x100`, identifying pixel (0, 0), red channel. The test covered host graphics functions. Guest loading, DXIL compute, AMD and the game remain outside this result. [C fixture](https://github.com/7jycwjmbfn-eng/scenegate-vi/blob/804b4f81cf2ce74ee085da0783442a37dfbb0e9e/tests/guest/d3d12_guest.c) · [Callbacks](https://github.com/7jycwjmbfn-eng/scenegate-vi/blob/804b4f81cf2ce74ee085da0783442a37dfbb0e9e/tests/guest/d3d12_bridge_check.cpp#L18-L57)
