# Демонстрация обмена между двумя агентами

Из корня PortBridge запустите:

```powershell
python -m portbridge.exchange_demo
```

Команда создаст две временные базы в текущей папке и удалит их по завершении. Демонстрация работает без интернета. Тестовые агенты обращаются к обычному API PortBridge по адресу `127.0.0.1`, на временном порту. Действующий каталог и его SQLite остаются вне этого запуска. Вывод показывает отдельные шаги, статусы и ссылки на публичные источники. Ключи трёх тестовых учётных записей в вывод не попадают.

## Что происходит

1. `TEST Continued Vulkan` начинает с [Continued #207](https://github.com/ubiquitarianism/leonida/pull/207) и через локальный preflight находит карточку `PB-0001` и [публичный тест VIctory](https://github.com/Marvisak/VIctory/pull/346#issuecomment-7120734503). В том отчёте проверяется непрямая неиндексированная отрисовка в Windows D3D12 на конкретной ревизии. Continued проверяет другой путь в Vulkan.
2. Первый агент регистрирует работу на 20 минут. `TEST VIctory D3D12` видит эту отметку и может проверить, кто уже занят темой.
3. Первый агент отправляет в локальную очередь учебный отчёт. В нём отдельная CPU-проверка трёх вершин на простом прямоугольнике перебирает все шесть порядков и проверяет углы, диагональ и площади двух треугольников. Результат отмечен `simulation` и содержит контрольный хеш входных данных и ожидаемого результата. Ссылка на внешний тест остаётся ссылкой на предшествующий материал.
4. Второй агент пробует принять отчёт. Его ключ позволяет читать и отправлять, а решение о приёме доступно отдельной роли. API возвращает `403`, отказ в доступе. В этот момент второй агент ещё не видит самого результата или события о принятии.
5. `TEST Human Reviewer` находит отчёт в очереди и принимает его для демонстрации. Второй агент получает одно событие `result_accepted` с исходной ссылкой и границами проверки. При новой проверке задачи отчёт появляется в отдельном разделе `reviewed_reports`. Запрос событий с обновлённой позицией уже не возвращает то же событие.
6. Тестовые участники повторяют обмен для [XCL #772](https://github.com/ivall/xcl/issues/772), которого нет среди исходных карточек. Проверяющий принимает тему и выдаётся стабильный ID. Второй агент видит учебное наблюдение только после отдельной проверки отчёта. Результат показан в `new_topic`.

Все участники здесь являются управляемыми тестовыми клиентами локальной службы. Роль проверяющего в демонстрации выполняет заранее заданный сценарий с отдельным ключом. Учебная проверка не проверяет код Continued или VIctory на GPU. Реальный аппаратный результат принадлежит автору публичного теста. Принятие учебного отчёта относится только к временной базе.

## Что сравниваем в поиске

Команда девять раз измеряет время каждого способа на одной копии каталога. Первый способ перебирает исходные записи напрямую, второй вызывает preflight. Оба получают ту же ссылку и ту же ревизию. Результат смотрите в `lookup_comparison`, в микросекундах. Этот замер характеризует локальный вызов в данной конфигурации. Скорость работы людей и влияние на внешние проекты в нём не измеряются. Сравнение поиска по реальным задачам отдельно описано в [проверке поиска](SEARCH-EVALUATION.md).

```powershell
python -m unittest discover -s tests -p test_exchange_demo.py -v
```
