# Wave32 scalar-mask liveness on current XCL

**Independently reproduced on AMD and NVIDIA.** DarkPanda69 ran the new edge test on the unchanged XCL compiler and reproduced the incorrect count on both an RX 9070 XT and an RTX 3060. Both passed with the PortBridge fix. In the GPU subset, AMD went from 704 to 706 passes, retaining the two existing #2115 failures and six skips. NVIDIA went from 706 to 708 passes with zero failures and 24 skips in both runs. The report covers the HLSL fix. Intel, title runs and direct-DXIL SSA projection were outside that check. Upstream review remains open. [Independent results](https://github.com/xcl-dev/xcl/issues/2584#issuecomment-7178879816)

The correction is available in the PortBridge XCL fork. A reproducer and its aggregate hardware results have been submitted to the upstream issue for review. The GPU test receipt omits the workstation-specific DXC installation directory. [Exact fork commit](https://github.com/akimfomin/xcl/commit/d3e7725f9f48c39c18e7b6e011ec76423edb0004) · [XCL #2584](https://github.com/xcl-dev/xcl/issues/2584)

In a Wave32 pixel program a carry or mask instruction can write only one scalar register. Treating the next register as overwritten can make a later population count return the wrong value at a triangle edge. The [original images and independent carry reference](../README.md) establish this on XCL's HLSL path. A width-only correction restored all 5,906 observations. It could also needlessly activate helper-quad ballots for a write whose adjacent register was live. This revision fixes the false kill while preserving the old lowering wherever only an unrelated neighbor is live.

For a potential mask write to `s[n]`, the original pair rule vetoed shortcut lowering when nominal live-out contained either `n` or `n+1`. The revised Wave32 pixel condition retains that veto and also vetoes when width-corrected live-out contains the *actual* destination `n`. Instantiating the lookup per destination preserves the distinction when an instruction has multiple destinations. Original scalar 64-bit instruction writes keep both kill bits. The change leaves Wave64 admission the same. Wave32 solves both liveness analyses during emission. Its incremental CPU cost was not separately timed. [Standalone compiler patch and regression tests](xcl-wave32-masks-current.patch)

The fix was implemented and tested on XCL `e1d84b7` as `ee2a37ca4461193c46eed161ea1d2cda988633d7`. All changes then applied without conflicts to live public main `08db8020d323bf478964fcc586152cce54959cfc`, producing review commit `181bf103bd9c56067c51a4333854bf235711f9b9`. For both WQM modes of the carry witness the precise compiler returned byte-for-byte the **same fixed DXIL** as the previously GPU-verified width correction. The two expected hashes are in [the witness receipt](witness.json).

## Open corpus and a physical downside avoided

Out of 218 configured public inputs, 195 Wave32 guest shader configurations produced complete paired HLSL. This includes two different binding layouts of Microsoft's BicubicUpsampleGammaPS. The width-only fix changed four configurations and replaced 32 local call sites with full ballots. The precise version returned stock HLSL byte-for-byte on all 195. The concrete correctness bug was demonstrated on the independently assembled carry shader. The incidence of this correctness defect in titles remains unmeasured. [Per-input shader hashes, calls and exclusions count](wave32-census.json.gz)

The tested Microsoft BicubicUpsampleGammaPS includes a real 400 × 225 input texture and outputs 800 × 450 pixels. The first fix increased DXIL from 26,156 to 31,156 bytes. Across three native D3D12 blocks on RTX 4070 Ti SUPER the stock shader took 0.03648 ms per draw in each block. The width-only correction took 0.09510, 0.10726 and 0.16730 ms. All 360,000 float4 pixels agreed between the two in each block. RGB differed from the original Microsoft HLSL by at most 2.4 × 10⁻⁷. The precise version regenerated the original 26,156-byte DXIL, SHA-256 `cd8c54df2b556e381bd9797a160348f22b52d084d8681a1eebce1ccaf9cea8e7`. The measurements refer to that exact program. The width-only fix remains in the record for comparison. [GPU receipts](mini-display.json) · [Input and layout](mini-input.json) · [HLSL and DXIL references](mini-hlsl.json)

## Reproduction

Apply the standalone patch to main `08db802` and use the compiler and hardware test commands in the [original regression](../README.md). To replay the census, build [the HLSL emitter](emit_wave32_hlsl.rs) once per pinned revision, using separate build directories. Use [scan_wave32_corpus.py](scan_wave32_corpus.py) to prepare the public Wave32 PAL programs, then [compare_wave32_admission.py](compare_wave32_admission.py) to compare the three emitters and all input digests. The functional comparison uses the [existing PortBridge open-scene renderer](../../open-scenes/README.md), the shader hashes above and the original Microsoft root signature. For the D3D12 CLI in that comparison, `--dxc` names `dxc.exe`.
