# Rendering an open raymarching scene through XCL

**How to use these results.** The raylib tables immediately below record the withdrawn lane-local lowering. The shader and its two cameras remain open workloads for the separate, opt-in SSA projection. On the stronger baseline SSA saved 19.2–19.6% of warm Vulkan draw time, with mixed results on a Microsoft filter. [Wave32 counterexample](../wave32-carry/README.md) · [Matched SSA comparison](../vulkan/strict-ssa/draft-overlap/README.md)

XCL rendered Inigo Quilez's raymarching scene from raylib at the sample's original 800×450 resolution. On an NVIDIA RTX 4070 Ti SUPER, changing how XCL represents pixel mask values reduced median GPU draw time from 7.375 to 1.503 ms for the default camera and from 7.669 to 1.637 ms for a second camera. All 360,000 RGBA32F pixels matched the whole-mask XCL baseline bit for bit in every paired capture. The unmodified OpenGL shader on the same GPU took 0.578 and 0.649 ms respectively. The default camera was held at raylib's initial viewpoint at time 1.0 s. The second camera used an explicitly recorded position and time 2.75 s. Each camera was rendered in five alternating fresh-process pairs. A full-target priming draw preceded eight full-target draws timed using the D3D12 direct queue. The GL reference used a separate process, the original loose uniform declarations and five GL_TIME_ELAPSED queries of eight draws each. GPU intervals cover the pixel workload plus its full-screen triangle. The original application window, controls and overlays were outside the test. In three separate single-draw trials, the whole variant spent 882.609, 866.990 and 866.328 ms in the synchronous CreateGraphicsPipelineState call alone. The local variant completed setup, one draw, the fence, CPU readback and subsequent GetCachedBlob in 415.857, 423.370 and 439.777 ms. Thus the saving through the first available 800×450 CPU image was at least 466.75, 443.62 and 426.55 ms in the corresponding pairs. The conservative time ratios are 2.122, 2.048 and 1.970. The interval starts with the common vertex shader and translated pixel bytecode already prepared. Shader translation, user-facing presentation and the original application loop lie outside it. The four-mode run used a balanced Latin square with four trials, 800×450 pixels and the same camera. Median ready draw times were 7.347 ms for whole, 5.099 ms for packed, 1.593 ms for local and 1.431 ms for local-packed. Median native creation times were 887.5, 796.1, 391.0 and 381.3 ms. All four images agreed in every trial. A 200-ms NVIDIA telemetry trace recorded P0, a 2,805 MHz graphics clock and a 10,501 MHz memory clock in all 313 samples. The GPU driver was 617.14. The workstation also had background GPU activity. In 24 telemetry samples outside every D3D guard-process interval, utilization ranged from 43% to 80%, with a median of 50%. Across the default-camera pairs, the observed whole/local ratio ranged from 4.66× to 5.00×, and across the second camera it ranged from 4.40× to 4.76×. An idle independent host is still needed for an isolated throughput estimate. ## Fidelity

Compared with the unmodified GLSL, 1,956 pixels on the default view and 1,594 on the second view differed by more than two 8-bit code values in at least one channel. Both whole and local shared these discrepancies. The 99th percentile of per-pixel maximum channel error was 0.001090 and 0.000775, respectively. The largest differences were about 0.055. The source computes a filtered checkerboard using derivatives within a data-dependent material branch. GLSL leaves derivatives within nonuniform control flow undefined. Arithmetic and driver differences can also contribute. This experiment does not attribute the residual error to a specific instruction. Comparisons used floating-point readbacks before PNG quantization. [Khronos GLSL derivative rules, §8.14.1](https://registry.khronos.org/OpenGL/specs/gl/GLSLangSpec.4.60.pdf) · [Original GL capture](ray800-primary/gl.png) · [Whole XCL capture](ray800-primary/whole.png) · [Lane-local XCL capture](ray800-primary/local.png)

This result establishes an execution and preparation benefit for this workload on this host. General equivalence for partially participating quads, scalar consumers and reconvergence needs separate proofs and controls. The original lowering has been withdrawn. A separate physical Wave32 carry-mask witness already disproves general correctness of the earlier mask assumption. [Wave32 carry control](../wave32-carry/README.md) Opaque PSO cache bytes and process commit do not identify the native machine code size or GPU-resident shader size.

## Where the transformation applies

The historical corpus enumerates all pinned Khronos fragment files, MiniEngine project pixel entries and Naga SPIR-V fragment snapshots. Of 214 attempted entries, 18 were excluded during input preparation. Two additional entries failed in both XCL arms on this stack. One uses unsupported scalar instruction S_BITREPLICATE_B64_B32 and another reaches a shared-memory validation error in a pixel stage. Both arms passed DXV on 194 entries. Ballot count and DXIL size both decreased in 33 entries, comprising 12/22 MiniEngine, 5/50 Naga and 16/122 Khronos. All other successful outputs had identical DXIL hashes. Deduplicating by RDNA digest gives 31 changed of 145 unique accepted programs. The two related Mobile NeRF entries account for 3,208 of the 3,880 ballots removed. Outside those two, the sum fell from 1,856 to 1,184. These are offline entry counts with the synthetic four-window root interface. They do not estimate frame frequency or original application behavior. A follow-up replay found overlapping set/binding decorations in 17 of the 24 MiniEngine SPIR-V entries. In the bicubic shader, AMD's PAL lowering loaded both the texture and the constants descriptor at the same address. Recompiling every declared pixel stage with distinct Vulkan ranges for DirectX texture, buffer, sampler and UAV registers changed 14 of the 22 extracted RDNA digests. The same 12 still benefited and the aggregate ballot count stayed at 432 → 48. Both extractions excluded the same two stages requiring a .text relocation. The original corpus statistics describe program shape. [Complete per-entry raw observations](timed-census.json.gz) · [Original resource audit](binding-aliases.json) · [Corrected project-wide PAL extraction](miniengine-corrected-project.json) · [Corrected XCL variants](miniengine-corrected-masks.json.gz)

The new raylib family was selected for dynamic controls, bounded loops, a single render target and independent source. The Julia and Mandelbrot pixel shaders produced identical whole and local DXIL. Quilez raymarching's guest Wave64 binary went from 546 to 54 ballot calls and from 177,688 to 100,196 DXIL bytes. Five within-process translations took a median 55.0 vs 32.5 ms. The observer timed just XCL translation before validation, disassembly and writes. Across the 161 historical entries with identical whole/local DXIL, the median of per-entry CPU-time differences was −0.008 ms, with 10th and 90th percentiles of approximately −0.076 and +0.061 ms. For the 33 changed entries the median was −0.458 ms. These measurements cover the whole XCL translation, including any savings in later lowering. They were collected on a shared CPU. ## Independent rendering of a Microsoft display filter

The second workload used Microsoft's original BicubicUpsampleGammaPS. A 400×225 linear floating-point texture from the original OpenGL raymarching image was enlarged to 800×450. The native D3D12 reference ran Microsoft's unchanged HLSL with its embedded PresentRS, the same texture, constants and full-screen triangle. The translated shader ran with the descriptor and constant offsets reported by AMD's pipeline compiler. An independent NumPy implementation also evaluated the 16-tap filter.

| Two complete trials | Original HLSL | XCL whole | XCL local |
| --- | ---: | ---: | ---: |
| Native PSO creation, first / second trial | 16.6 / 19.1 ms | 231.2 / 239.5 ms | 65.7 / 64.1 ms |
| GPU draw, first / second trial | 0.0130 / 0.0131 ms | 0.2151 / 0.1174 ms | 0.0253 / 0.0625 ms |
| Opaque PSO blob | 8,866 bytes | 58,546 bytes | 20,194 bytes |

Before/after XCL matched every floating-point RGBA pixel in both trials. The largest RGB difference from the original HLSL was 0.0000002384. The largest difference from the CPU oracle was 0.0000213. The temperature, frequency and background-load noise in this run did not support a stable GPU speedup estimate; each individual timing is retained. The system-memory guard stopped the third trial, which is recorded separately in the receipt. The bicubic gamma variant is a published display shader; this pinned MiniEngine runtime selects a different bicubic implementation. The live SDR-compatible presentation shader PresentSDRPS also rendered correctly in a separate smoke test. All 12,288 RGB pixels matched the original HLSL bit for bit. ### Comparison with a conservative projection

An alternative XCL lowering computes the lane's requested bit from the existing mask representation while preserving all ballot operations. Its comparison uses its own matched whole-mask translation on upstream e1d84b7d9153f86a97d2ec5d209d196046fc0bea. On the 800×450 SDR presentation stage, XCL whole and projected outputs matched in all 360,000 RGBA pixels, with exact RGB agreement against Microsoft's original HLSL. Native pipeline creation took 18.63 and 18.23 ms in one trial. This simple stage gave little room to improve. [SDR comparison](mini800-ssa-present/display.json) · [Shader identities](miniengine-ssa-inputs.json)

The bicubic filter is a counterexample to a general size or execution gain. Preserving all 193 ballots while reducing DXIL from 54,628 to 51,300 bytes increased the opaque PSO blob from 59,010 to 61,986 bytes. In two completed trials, whole and projected PSOs took 235.86→227.36 and 238.00→224.81 ms to create. Their GPU timings went in opposite directions (0.228→0.256 ms and 0.241→0.211 ms). All 360,000 RGBA values matched in both pairs. The largest RGB difference from original HLSL was 0.0000002384. Both complete trials used native → whole → project order. A following rotated trial was stopped by the memory guard. Neither a GPU execution win on this stage nor a change in native machine-code size has been established. ## Reproduce

1. Use the XCL overlap stack in the linked instructions. Its tracked tree is 07622a771150d9f14278426f6402080b30f067ca. Apply open-scene-draw.patch to this test checkout and build its XCL lib tests. Copy observe_timed.rs into crates/xcl/examples and build the release example. The observer and the XCL test changes are GPL-2.0-only, following the source project. The guard source lives in the parent PortBridge pipeline-readiness directory. [Pinned stack and instructions](https://github.com/akimfomin/PortBridge/blob/fcc1d7086ebecd6661bf18f0ef2b6f7210054e2c/research/pipeline-readiness/structural-suite/UPSTREAM-OVERLAP.md) · [Draw harness changes](open-scene-draw.patch) · [Translation timing observer](observe_timed.rs)
2. Check out raylib at 7aeef5775435ed9f57890bf3c1b53279f6b0866a in a clean checkout. Provide the pinned PortBridge corpus helpers, glslang, SPIRV-Tools, AMD's RGA 2.12 amdllpc, and LLVM readobj to prepare_raylib.py. The helper checks the checkout and the PAL compiler digest. It preserves the original operations, converts OpenGL loose uniforms to an explicitly laid-out Vulkan push-constant block and accounts for the different pixel-coordinate origin. The optional Wave32 run changes the fragment stage wave size in the pipeline document dumped by AMD's own compiler. It verifies the resulting ELF metadata. [Original licensed shader](https://github.com/raysan5/raylib/blob/7aeef5775435ed9f57890bf3c1b53279f6b0866a/examples/shaders/resources/shaders/glsl330/raymarching.fs) · [Preparation program](prepare_raylib.py)
3. Run mask_census.py on the resulting manifest with the built observer, Microsoft's DXC 1.9.2609.5, DXV and a new output directory. Set PB_TRANSLATION_REPEATS=5 when collecting translation timings. Each input digest is checked, both outputs are validated, and every variation is recorded. Setting the four root windows, UMA high dword 4 and XCL_DXIL_SWITCH_READ_FUSION=1 reproduces the tested translation interface. [Paired CPU replay](mask_census.py)
4. Run render_raylib.py with the repo, prepared manifest directory, mask output directory, guard executable, XCL lib test executable, dxc.exe and a fresh output directory. Use Python with NumPy, Pillow, ModernGL 5.12.0 and glcontext 3.0.0. Supply --scene raymarching --size 800 --height 450 --draws 8 --pairs 5. Add --other-view --time 2.75 for the second camera. The guard checks memory headroom, caps job memory and limits execution time. A missing image, zero timestamp, unrecognized PAL layout, shader digest mismatch or skipped GPU test fails the run. Independent contributors can use the [SSA projection comparison](../ssa-mask-projection/README.md). The command above reproduces the archival local-mask captures. [Renderer and comparisons](render_raylib.py)
