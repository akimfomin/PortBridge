# XCL structural compiler matrix

The matrix replays two pinned open shader cohorts through one XCL executable built at `f87aa761e01a3d3ef185c474f5d0d2521736799b`. The baseline is XCL `e1d84b7d9153f86a97d2ec5d209d196046fc0bea` with scalar reload CSE from XCL #2446 applied as `bddf7466a6a4886f063da629e8f733f7d30e7547`. CSE stays enabled in every arm. The replay uses the same AMD gfx1030 PAL pixel instruction stream and the same synthetic XCL interface across the arms for a shader. The proved configuration supplies UMA high dword `4`. The manifest records source and RDNA hashes, XCL and tool hashes, independent Microsoft DXV validation, and the successful DXIL shape and digest. [XCL #2446](https://github.com/xcl-dev/xcl/pull/2446)

- The first cohort includes every MiniEngine pixel `FxCompile` entry and each Naga fragment snapshot at the pinned revisions. Seventy-two of 76 attempted entries produced standalone inputs for replay. [MiniEngine at `68a2b1e9`, MIT](https://github.com/microsoft/DirectX-Graphics-Samples/tree/68a2b1e97f71642924e74c7757ca21756ad221b5/MiniEngine) · [Naga at `c76dea03`, MIT or Apache-2.0](https://github.com/gfx-rs/wgpu/tree/c76dea031c688ecef0050dbf60506fff128fb23f/naga/tests/out/spv)
- The independently authored cohort includes 138 `.frag` files under the pinned Khronos sample tree. Fourteen entries were excluded before XCL translation. Two further inputs could not validate as XCL pixel stages because the translation uses thread-group shared memory. Those two exclusions occur across every tested arm. [Khronos Vulkan Samples at `979aefaa`, Apache-2.0](https://github.com/KhronosGroup/Vulkan-Samples/tree/979aefaa5f2f4bd30efe035ca5a39444cc24ab9f/shaders)
- Every root-window combination of aperture specialization (A), guard fusion (G) and switch fusion (S) was tested. The descriptor-heap experiment tests `off`, `a`, `g` and `ag` with S disabled. S requires consecutive raw-read switch regions with identical selectors and keys. The heap-window lowering normally selects descriptors dynamically. A shader could still contain its own switch. The heap matrix tests A/G interaction and leaves S outside its measured scope.

The original extraction only accepts fragment code without unresolved text relocations and records PAL input enables, target and depth exports, interpolant count, and wave size. XCL's synthetic interface omits original application resource bindings and interpolation. Shape and DXV results measure translated structure and validation. Original application behavior, GPU timing and native code size require separate evidence. Samples can produce identical RDNA instruction streams and the matrix counts entries. [Open corpus extraction](https://github.com/akimfomin/PortBridge/blob/3de1234dfd0cc137664ae17caad50ce02bb99bde/research/pipeline-readiness/corpus/README.md)

Use `combined_matrix.py --help` for the replay options. Point `--input` at the original extraction manifest and `--out` at a new output directory. Use `--layout heap-4 --aperture-guard-only` for the heap comparison. Public metadata contains source-relative paths and hashes. The generated DXIL and disassemblies remain available separately for hardware measurements.
