# XCL #2080. Measure scratch allocation demand by backing epoch

The RTX comparison found a one-buffer penalty and benefits for four and sixteen small buffers when one fixed 1 MiB heap was shared. This source patch adds opt-in diagnostics for the exact committed scratch calls in XCL #2080 at `12cd2fa9`. It can establish whether counts and sizes in actual recorded backing-allocator batches resemble that benchmark. [Pin](https://github.com/xcl-dev/xcl/blob/12cd2fa9a25eb7e04b650ddf3080489981aa40a0/crates/xcl/src/hle/d3d12x/real/dispatch_chain.rs) · [Hardware result](https://github.com/akimfomin/PortBridge/blob/10ce997e6b705b1bb3d173b0412551dd2dc91b6b/research/xcl-dxil-night/scratch-placement/README.md)

Set `XCL_SCRATCH_ALLOCATION_STATS=1` in the candidate process. The existing backing retirement hook logs per-batch request counts up to 64 KiB, 256 KiB and 1 MiB, then above that. It also logs summed requested bytes and host time spent inside the successful recorded allocation calls. At the existing totals report it logs snapshots of active batches and a count of failed scratch allocation calls. Use retired batches for completed lifetime distributions and active rows only as a point-in-time snapshot. The log contains aggregate counters without shader contents or resource addresses.

The patch uses the original allocation, fallback, reference and recording ownership. Diagnostics occur after removal from the existing records map and after releasing the retired recordings. The reset caller can still hold its allocator synchronization while logging, so use the option to sample demand and avoid comparing overall runtime timing with it enabled. The extracted aggregation loop passed three tests under Rust edition 2021, including bucket edges and saturating sums. `git apply --check --whitespace=error-all` passed against the exact pinned source. The complete XCL runtime and diagnostics in a live workload still need verification.
