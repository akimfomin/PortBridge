# XCL keeps the PSO blob byte budget consistent

On XCL `cbc296ab65a2661a61e3e2da109134bcd5319f60`, concurrent publishers of the same compute or graphics key can both find a miss, then increase the byte counter and insert under separate acquisitions of the cache mutex. The later insert overwrites the value and leaves its predecessor charged. When a rejected blob is removed, the actual value is subtracted once and the earlier charge stays. [Pinned production source](https://github.com/xcl-dev/xcl/blob/cbc296ab65a2661a61e3e2da109134bcd5319f60/crates/xcl/src/hle/d3d12x/real.rs#L4221-L4264)

The [patch](xcl-blob-accounting.patch) charges bytes only when inserting into a vacant entry under the existing map lock. The driver call, scheduling, and disk persistence run outside the edited block. A concurrently rejected old blob can still remove a later entry for that key, and the removal subtracts the bytes of the entry it removes. Hardware behavior and title startup time remain unmeasured.

| Deterministic CPU check | Existing source | Patched source |
| --- | --- | --- |
| Four callers publish one 16-byte key | 64 bytes charged, 16 present | 16 bytes charged, 16 present |
| Remove the rejected key twice | 48 bytes charged, 0 present | 0 charged, 0 present |
| Refill the key | 64 bytes charged, 16 present | 16 bytes charged, 16 present |
| Fill a 64-byte test budget using independent keys | 1 of 4 blobs fit | All 4 blobs fit and a fifth is blocked until a slot is freed |

Both caches pass the same checks. The fixture extracts the exact map, lookup, insertion, and rejection routines from Git. It replaces driver blob retrieval with supplied bytes and pauses callers between the precheck and publication. The 64-byte capacity control reduces only the two capacity constants in its generated copies. Empty and failed retrieval, null handles, and below-threshold DXIL leave the cache unchanged. [Captured results](accounting-results.txt)

Current XCL [#2001](https://github.com/xcl-dev/xcl/pull/2001) head `1f1d681439db77ea01a656dc8fc65aa4eabc7d1b` contains the same keep and forget implementations as main. [#1006](https://github.com/xcl-dev/xcl/pull/1006) head `19381fbd91c689b948774a5f6c15b8a233998047` replaces the graphics blob path and keeps the same compute accounting sequence.

## Reproduce

Run from the folder containing this document, with Git, Python 3 and a Rust linker toolchain. The checker creates `generated/`, extracts the baseline routines from the pinned Git object and reads the patched version from the checkout. It expects exit `2` for the baseline and `0` for the patched source, with both actual budgets and the small capacity control.

```text
git clone https://github.com/xcl-dev/xcl.git xcl
git -C xcl checkout --detach cbc296ab65a2661a61e3e2da109134bcd5319f60
git -C xcl apply --check ../xcl-blob-accounting.patch
git -C xcl apply ../xcl-blob-accounting.patch
python run_accounting.py --repo xcl
```

The checker accepts `--rustc` and `--linker` paths when the toolchain needs them. Local verification used rustc 1.100.0 for `x86_64-pc-windows-gnullvm` with LLVM-MinGW. No external dependencies, graphics API calls, or game materials are used. XCL excerpts generated by the fixture retain the project's GPL-2.0-only license.
