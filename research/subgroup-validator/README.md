# Subgroup Transport Contract

PortBridge research component for checking whether a compute-shader translation preserves one lane read. It returns a concrete destination lane, selector and pair of guest and host masks when a proposed lowering can change a defined result. One shared model now checks emitted SPIR-V from Continued and Direct DXIL from XCL. Each adapter recognizes a narrow local form and identifies unsupported shapes explicitly. [Direct DXIL replay](DXIL.md)

## Reproduce

Use Python 3.11 or newer. Run these commands from this directory. The base model and its tests use the standard library.

```text
python -B -m unittest discover -s . -v
python -B run_cases.py
```

The optional replay reads the two handwritten synthetic workloads in public Continued commit `1bedab24c39d0b3ae325f6f0f6c43e47bbb6430e`. Use a clean checkout at that commit and a SPIRV-Tools bin directory containing `spirv-as` and `spirv-val`. The observed run used SPIRV-Tools `v2026.4-119-g3c8fd352` targeting Vulkan 1.3. The replay writes assembly, binaries, SHA-256 values, model results and interpreter outputs under the output directory. [Continued commit](https://github.com/ubiquitarianism/leonida/commit/1bedab24c39d0b3ae325f6f0f6c43e47bbb6430e) · [SPIRV-Tools](https://github.com/KhronosGroup/SPIRV-Tools)

```text
python -B check_continued.py --checkout ../continued --spirv-tools /path/to/spirv-tools/bin --output ./continued-replay
```

| Input | Recognized reads | Result |
| --- | ---: | --- |
| Continued `cs_w64x_bpermute` | 3/3 | All three pass with 32- or 64-lane host subgroups and guest EXEC contained in host participation. Continued's interpreter independently returns the same eight expected words in both layouts. |
| Continued `cs_w64x_partial` | 2/3 | Both ballot-guarded reads pass the same model check. The third read is a different operation and remains unmodeled. Continued's interpreter passes the 40-active-lane workgroup in a 64-lane subgroup. |
| Half base removed from `cs_w64x_bpermute` | 3/3 | Each read fails 8,128 of 36,224 projected classes on the 64-lane host, with no model failures in the aligned 32-lane layout. The interpreter changes output word 1 from 316 to 92 on the 64-lane host. |

All four assembled and passed the standard Vulkan 1.3 IR validator. The original five recognized reads pass 24,064 projected classes each per host size when host participation contains guest EXEC. Allowing logically active source lanes to be absent from host participation refutes the same reads in 3,968 of 32,000 projected classes each per host size. This is a counterexample to the weaker precondition. No such reachability is established for the original programs. The counts describe equivalence classes, with no estimate of workload frequency or runtime speed. ## Proof domain

The model keeps separate symbols for old destination data, current data from each lane, known zero, undefined results, and prior-epoch data. A defined guest result must retain the same symbol. Host undefined data fails this check when the guest result is defined. Each destination and normalized selector is tested against every relevant combination of three guest-mask bits and one source participation bit. The three guest bits are the destination and the guest and host selected sources. Extra mask bits cannot affect that read under this model. The standalone tests compare projected failure witnesses against every allowable mask combination on four lanes for 992 configurations.

The SPIR-V adapter matches one typed local def-use graph in a compute module. It binds the byte add and shift, 32-lane mask and subgroup-local base, data zeroing under guest EXEC, subgroup ballot, fallback to the reader's own index, guard on the shuffled result, and write-back that retains the old value when the guest destination is inactive. It relies on structural validation with SPIRV-Tools. The specification leaves a shuffle result poisoned if the chosen invocation does not participate or the index is out of range. Ballot lookup beyond the subgroup size also yields poison. [SPIR-V shuffle](https://registry.khronos.org/SPIR-V/specs/unified1/SPIRV.html#OpGroupNonUniformShuffle) · [SPIR-V ballot lookup](https://registry.khronos.org/SPIR-V/specs/unified1/SPIRV.html#OpGroupNonUniformBallotBitExtract)

The result is conditional on the declared virtual-to-physical lane layout, common dynamic participation at the ballot and shuffle, and the supplied address, data, EXEC and old-destination bindings. The local adapter checks the shape of the arithmetic and the relationship between its uses. It reports the bindings and observed byte offset for comparison with the source instruction. It does not derive these inputs from the surrounding program or recover the guest opcode's offset independently. It accepts only shuffles in the entry function and a local destination without intervening effects between the old-value load and final store. It covers one 32-bit operation, without reconvergence analysis, arbitrary shaders, helper invocations, hardware layout inference, or memory-order proofs. The actor lane is present in both participation domains. A modeled current-snapshot exchange assumes that the memory synchronization contract has been separately established. Unknown IR shapes receive an explicit unmodeled status. [HLSL WaveReadLaneAt semantics for future DXIL work](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/wavereadlaneat)

## Why this is the primary research

Open reports establish repeated portability cost in independent implementations. XCL contributors measured native `ds_bpermute_b32` half-wave behavior on gfx1031 and gfx1036, matching the AMD guide's descriptive section. The gfx1036 report covered 21 bpermute cases across all 64 lanes, including partial EXEC and nonzero offsets. XCL #1022's open head fixes both HLSL and direct DXIL paths, with reported same-head tests on RTX 3070 and RX 7600 XT and separate Arc A770 coverage of the HLSL test. These are upstream measurements. The PortBridge replay here only used the CPU. [AMD RDNA2 ISA, §10.4.4](https://docs.amd.com/api/khub/documents/Et~wpu9g~Ffl7d9q0QZ~Og/content#page=104) · [Measurements for XCL #772](https://github.com/xcl-dev/xcl/issues/772) · [XCL integration evidence](https://github.com/xcl-dev/xcl/pull/1022) · [XCL reviewed revision](https://github.com/xcl-dev/xcl/commit/7e1b659cfcd95c37d8710c85adb3753847455575)

PortBridge MCP's expanded compiler search found both Continued #770 and AMD's public Vulkan driver report #138. The latter reports a separate wave64 failure where an EXEC-narrowed read loop consumed a stale register on specific driver and GPU combinations, despite valid input SPIR-V. The current check examines a shader translator's SPIR-V, so it cannot reproduce or diagnose that native driver failure by itself. The direct GitHub check located the newer public receiver revisions. The locally archived `7b1836f` labeled #4300 concerns SCC liveness and was excluded from the transport evidence. [Continued model tests](https://github.com/ubiquitarianism/leonida/pull/770) · [AMD driver report](https://github.com/GPUOpen-Drivers/AMD-Gfx-Drivers/issues/138)

Continued provides the SPIR-V adapter target, and XCL provides the Direct DXIL target. VIctory remains a prospective target with a separate lowering strategy. VIctory #2176 explicitly makes its two host halves behave as separate waves. Under that approximation, a full-wave read of selector 40 by guest lane 0 maps to host lane 8. The two results can differ even when all lanes participate. This is a concrete compatibility bound of the approximation. It does not determine the end-to-end behavior of any title. [VIctory proposed lowering](https://github.com/Marvisak/VIctory/commit/3feadc6) · [VIctory proposal and scope](https://github.com/Marvisak/VIctory/pull/2176)

ShaDiv tests graphics backends by generating divergent shaders. Alive2 established a refinement-based construction for validating LLVM IR transformations. This component checks a bounded transport contract by exhausting its relevant mask cases and emitting a readable witness. The next validation gate is an additional named defect or independently confirmed participation or layout premise on open workloads. The present component adds a local diagnostic and makes no measured claim about total driver correctness, compilation speed, or frame time. [ShaDiv, PLDI 2025](https://daoyuan14.github.io/papers/PLDI25_ShaDiv.pdf) · [Alive2, PLDI 2021](https://web.ist.utl.pt/nuno.lopes/pubs/alive2-pldi21.pdf)

## Reserve research

Investigate the cost of compiling generated shaders with large, repeated control-flow regions. The actionable first experiment is to compare duplicated branch bodies against a form that computes branch parameters and then uses one shared typed body. Use the same modulo-32-bit operations, selected memory reads, final output, workgroup dimensions, and dynamic per-lane inputs for each variant. Sweep region count and fan-out separately. Include a same-size straight-line control and a loop-carried control. Baselines include the unchanged generator, DXC `-O1`/`-O3`, SPIRV-Tools `-O`, and cache/precompile when measuring an application. Record generation time, compiler time, cold driver pipeline time, peak process memory, correctness and GPU dispatch time separately. Avoid reusing incident-specific assets. Start with normalized synthetic shaders and add public Dolphin generated-shader inputs or a sample engine before claiming breadth. Publish cases with no benefit and stop if the existing compiler already produces equivalent IR or if a cold-tail win fails to survive dispatch or the full startup budget.

XCL #1269 supplies evidence for the severe tail, with an upstream report of a pipeline compile still outstanding after 33 minutes alongside process memory above 14 GB on a particular generated shader. The logged corpus is private and was not used for this study. Dolphin's generated ubershaders and background specializations establish a separate engine dealing with compilation cost and runtime trade-offs. Its public source has generated branch selection and loop motifs. There is no evidence yet of the same 33-minute mechanism in Dolphin.
