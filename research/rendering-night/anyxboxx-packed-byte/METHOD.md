# AnyXboxX portable RDNA2 byte pack

Base: AnyXboxX `b10149942d972ed2b1d7b721cce63347f086a0f8`. This changes AnyXboxX's Python reference interpreter and HLSL emitter. The separate VIctory submodule is outside this patch. KainanP's #151 explicitly left `v_cvt_pk_u8_f32` open for lack of a sufficiently precise reference. [AnyXboxX #21](https://github.com/LooperSalty/AnyXboxX/issues/21) · [AnyXboxX #151](https://github.com/LooperSalty/AnyXboxX/pull/151)

The AMD reference defines the three operands and byte insertion. The expected values come from public measurements by adriadam10 on gfx1035 and zmeizy on gfx1030. TechLevelZero's gfx1036 measurements distinguish all runtime rounding and denormal modes. These were used as behavioral evidence. The implementation and the generated probes were written locally. [AMD RDNA2 ISA](https://www.amd.com/content/dam/amd/en/documents/radeon-tech-docs/instruction-set-architectures/rdna2-shader-instruction-set-architecture.pdf) · [Default rounding and modifiers](https://github.com/boykopovar/AnyPS5/pull/501) · [Directed rounding](https://github.com/boykopovar/AnyPS5/pull/6011) · [Runtime modes](https://github.com/boykopovar/AnyPS5/pull/10595)

The new handler implements default round-to-nearest-even, unsigned saturation, NaN→0, the low two selector bits, preservation of the other bytes, EXEC and `abs`/`neg` on the floating operand. The Python reference uses Python's ties-to-even conversion. The HLSL helper uses integer arithmetic on IEEE-754 bits, avoiding dependence on the driver's implementation of a floating rounding intrinsic.

The raw AnyXboxX entry point has no `FLOAT_MODE` input or mode state. Directed rounding configured outside the raw instruction bytes is outside the supported input assumptions. Parsed mode-setting instructions such as `s_round_mode` still fail explicitly. A negative control tests this in both paths. Output modifiers and modifiers on byte-selector/word operands also refuse. Flushing or preserving a denormal makes no output difference in the supported nearest-even mode.

## Verification

- Baseline failed at standard decoded VOP3 `0x15E`. Patched reference runs 16 hardware-derived cases over the 32-lane fixture, with byte selectors, destination/source aliasing, and inactive lanes covered. Source emission, float source modifiers and refusal controls passed.
- Portable test subset passed 56 tests. Eleven cases needing other prerequisites or the full suite selection were skipped. All 659 tests collect and the nine README counts agree. Targeted Ruff and `git diff --check` passed.
- The exact generated HLSL helper is valid integer C++ after defining `uint` as `std::uint32_t`. The proof compiles it as a standalone CPU function and compares 137,384 packed words with an independent floating `nearbyint` oracle. It includes the immediate neighbors of every half-integer, edge cases, eight selector words, and a seeded sweep of arbitrary inputs.
- The existing HLSL shader execution fixture includes an optional real GPU comparison. Separately, `pack-native-fixture.py` generated one byte-pack-only shader and two synthetic memory images. The exact unpatched base refused the HLSL translation. DXC 1.9.2609.5 compiled the patched output as `cs_6_0` on CPU. A guarded run on RTX 4070 Ti SUPER completed one native dispatch. The entire 131,200-byte result matched, including 24 active packed words and eight inactive words. [Runner transcript](native/rtx-stdout.log) · [Exact comparison](native/rtx-verified.log)

`b1014994-pack-byte.patch` contains the candidate. Apply `b1014994-pack-byte-fixture.patch` to an otherwise unchanged base for the failing regression. Logs are `b1014994-pack-baseline.log`, `b1014994-pack-patched.log` and `pack-helper-probe.log`.

## One-group native readback

`proof/native/pack.dxil` is the CPU-compiled shader. Each 131,200-byte input and expected image is generated by the fixture. The expected whole-buffer SHA-256 is `6FF3DAEA6E66E586E660F4112CA576810D4182F151E98FE544C9CF7F74C46445`. The 32-lane group packs 24 words and preserves eight inactive words. The entire memory image must match.

The existing native runner was built for an earlier AnyXboxX worktree. Its `runtime/gpu_runner` sources match the current base byte for byte, so no fresh native build is required for this one-group dispatch. In an approved hardware window, from the patched checkout:

```powershell
$env:ANYXBOXX_GPU = 'NVIDIA GeForce RTX 4070 Ti SUPER'
$runner = (Resolve-Path <path-to-current-native-runner>).Path
Copy-Item -LiteralPath proof/native/pack.in.bin -Destination proof/native/pack-rtx.bin
& $runner proof/native/pack.dxil proof/native/pack-rtx.bin 1
if ($LASTEXITCODE) { exit $LASTEXITCODE }
python proof/pack-native-fixture.py --verify proof/native/pack-rtx.bin
```

The original input stays intact. The runner writes into the copied memory image. Named adapter selection prevents software fallback. The unpatched checkout refused `v_cvt_pk_u8_f32` during source translation and has no negative DXIL to dispatch.
