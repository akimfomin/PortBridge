# AnyXboxX #188 — faster GFX10 subresource copies

Based on Lewandox’s [AnyXboxX #188](https://github.com/LooperSalty/AnyXboxX/pull/188) at `22c1cf973e7e2ad89fbec8e801d77d287c48729f`. Its GFX10 implementation credits AMD Mesa addrlib under MIT. The [patch](anyxboxx-gfx10-copy.patch) preserves that attribution and adds a synthetic Rust test under AnyXboxX’s contribution terms.

The address equation is a parity of X, Y and slice bits. The copy path evaluates each column’s X contribution once, evaluates Y once per row, then combines them with the slice contribution and pipe-bank XOR. It uses whole coordinates, including the origins of mip tails. Padded linear layouts copy one logical row at a time. Layouts of up to two elements on each side within one macroblock use a direct address calculation. The existing `element_offset` is the independent oracle used by the tests. [Pinned copy code](https://github.com/Lewandox/AnyXboxX/blob/22c1cf973e7e2ad89fbec8e801d77d287c48729f/rust/anyxboxx-texture/src/gfx10.rs#L276-L368) · [Pinned equation](https://github.com/Lewandox/AnyXboxX/blob/22c1cf973e7e2ad89fbec8e801d77d287c48729f/rust/anyxboxx-texture/src/gfx10_eq.rs#L226-L240)

For a tiled W×H subresource, the parity work drops from W×H evaluations to W+H+1. The copy still visits every element. A local column table uses at most 256 KiB on x64 at the supported 16,384-element maximum width, or 64 KiB for BC layouts. The direct small-tile and linear paths skip this allocation.

## Correctness

Both branches pass all eight upstream GFX10 tests and the three added oracle tests. The latter exercise 104 synthetic layouts with all 15 modes and five element widths, compressed blocks, varied pipe and packer configurations through 64/32, mip tails, array slices, and explicit invalid-buffer checks. Before each write they compare detiling against `element_offset`. After the write they compare every byte of the entire backing surface, including neighboring subresources, row and block padding, and extra bytes beyond the declared surface size. ## Warm CPU copy timings

Medians across four alternating baseline/candidate pairs on an Intel Core i5‑13600KF, Windows x64, `rustc 1.100.0` (`0ef1bc386`), `-C opt-level=3`, default target CPU. In every child a round trip warms and verifies the working buffers before timing. Timed tiling reuses a backing buffer. Timed detiling includes its returned vector allocation. Every pair produced identical backing and linear fingerprints. Game loading, GPU execution, cold-copy timing, and BC7-to-pixel decoding are outside this measurement. [Raw samples](samples.csv) · [Medians](summary.csv) · [Compiler](compiler.txt)

| Synthetic surface | Tile before → after | Detile before → after |
| --- | ---: | ---: |
| 1920×1080 RGBA8, 64 KiB XOR | 35.620 → 2.506 ms | 36.338 → 3.708 ms |
| 3840×2160 BC7, 64 KiB S | 8.854 → 1.536 ms | 10.147 → 1.698 ms |
| 4096×4096 BC7, 64 KiB D XOR, 64 pipes | 18.186 → 1.777 ms | 20.564 → 3.709 ms |
| 1919×1079 pitched linear RGBA8 | 6.783 → 0.450 ms | 7.334 → 1.462 ms |
| BC7 mip tail, nonzero array slice | 8.593 → 1.275 µs | 8.700 → 1.332 µs |
| 8192×1 RGBA8, 4 KiB XOR | 113.484 → 65.698 µs | 112.026 → 83.037 µs |
| 1×8192 RGBA8, 4 KiB XOR | 115.784 → 71.548 µs | 118.207 → 62.208 µs |

The four boundary controls cover 1×1, 2×1, 1×2 and 2×2 BC7 blocks. After using the direct small-tile path, the single-block median is 20 → 18 ns for tiling and 50 → 49 ns for detiling. Treat these nanosecond readings as overhead controls. The unguarded prototype had been slower on a single BC7 block.

## Reproduce

From this folder, use a Git client, Python 3 and a Rust toolchain. A sparse checkout selects only the source and Rust tests for this library. The package compares the pinned source from Git with the patched working copy at the same commit. It builds with standalone `rustc` and has zero external crate dependencies.

```text
git clone --filter=blob:none --no-checkout https://github.com/LooperSalty/AnyXboxX.git anyxboxx-open
git -C anyxboxx-open fetch --no-tags --filter=blob:none origin refs/pull/188/head
git -C anyxboxx-open sparse-checkout set --no-cone "/rust/anyxboxx-texture/src/*.rs" "/rust/anyxboxx-texture/tests/*.rs"
git -C anyxboxx-open checkout --detach 22c1cf973e7e2ad89fbec8e801d77d287c48729f
git -C anyxboxx-open apply --check ../anyxboxx-gfx10-copy.patch
git -C anyxboxx-open apply ../anyxboxx-gfx10-copy.patch
python compare.py build --repo anyxboxx-open
python compare.py check
python compare.py bench --pairs 4
```

The build command also accepts `--rustc` and `--linker`. All input bytes are generated by the Rust tests or runner. The focused test binaries cover the GFX10 suite and additional oracle tests. The BC7-only test binary with `sha2` and the broader AnyXboxX suite were outside the focused verification.
