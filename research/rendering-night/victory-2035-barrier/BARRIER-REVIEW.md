## Two source findings

1. **One console wave can span host waves with a shared-buffer dependency.** The revised selector still has no memory-effects input. Consider a zero-LDS compute group with 64 threads, a console wave64 and a host wave32. Use a loop with a lane-dependent exit which all invocations pass on the first iteration. In that first epoch one half writes shared buffer data before the synchronization point, and the other half consumes it afterwards. With no console-lane operations requiring the wave pin, the lowering can select mode `10` even when it already recognizes the UAV write and would have emitted mode `11`. The `s_barrier` is reached uniformly in that first epoch. The later possible nonuniform exit causes the same site to lose group sync in every epoch. For a genuinely divergent multi-console-wave group, the selector keeps group sync, which still needs a convergence proof or uniform lowering before dispatch. [Compute wave pin](https://github.com/Marvisak/VIctory/blob/bfb7c39c7ba34209ea09d24d5e69f17607af3688/crates/victory-shader/src/emit/lower.rs#L606-L649) · [Barrier selection](https://github.com/Marvisak/VIctory/blob/bfb7c39c7ba34209ea09d24d5e69f17607af3688/crates/victory-shader/src/emit/lower.rs#L2956-L2981) · [Flag emission](https://github.com/Marvisak/VIctory/blob/bfb7c39c7ba34209ea09d24d5e69f17607af3688/crates/victory-shader/src/emit/lower.rs#L3410-L3422)
2. **The existing `writes_uavs` flag misses Flat global stores and atomics.** `writes_uavs` recognizes image and buffer stores or atomics. `flat_write` emits a `rawBufferStore.i32` for `Fields::Flat` and lowers its atomics separately. The flag can therefore omit the UAV fence for a shader whose global store goes through a UAV. This predicate predates #2035. The inherited mesh `no_barrier` shortcut can skip the barrier before the selector runs and would need a separate audit before sharing an effect proof between the two paths. [UAV predicate](https://github.com/Marvisak/VIctory/blob/bfb7c39c7ba34209ea09d24d5e69f17607af3688/crates/victory-shader/src/emit/lower.rs#L596-L605) · [Flat store generated op](https://github.com/Marvisak/VIctory/blob/bfb7c39c7ba34209ea09d24d5e69f17607af3688/crates/victory-shader/src/emit/lower.rs#L1056-L1106) · [Inherited mesh shortcut](https://github.com/Marvisak/VIctory/blob/bfb7c39c7ba34209ea09d24d5e69f17607af3688/crates/victory-shader/src/emit/lower.rs#L681-L694)

A memory fence orders memory operations. The group sync also waits for the other invocations to reach the same dynamic barrier. For the first epoch the static model supplies a console-side handoff in which the shared store is completed before consumption. On the host a producer completes the shared store, then arrives. A consumer arrives, then reads that location. With a first-epoch rendezvous and the modeled memory visibility, the read is always `1`. With a fence alone, an allowed schedule can read the old `0` before the producer runs. The model grants the fence correct visibility for an already completed store, so the missing arrival edge is independent of flag selection. [Microsoft GroupSync contract](https://learn.microsoft.com/en-us/windows/win32/direct3dhlsl/groupmemorybarrierwithgroupsync) · [DXIL barrier flag rules](https://github.com/microsoft/DirectXShaderCompiler/blob/main/docs/DXIL.rst)

## Sufficient eligibility rule

| Proof available at the barrier | Safe action |
| --- | --- |
| All workgroup invocations reach the same ordered dynamic barrier instance, including across any loops and early exits | Keep group sync and the required memory fences |
| Convergence is absent or unknown, and no other invocation can observe its ordering | Omit group sync while retaining the relevant memory fences |
| Either shared effects or their ordering are possible and convergence is absent or unknown | Require a convergent lowering or reject this path before dispatch |

The second row needs a real effect proof. A conservative starting point is a positively recognized, reachable path with register-private operations and no observable LDS, UAV, atomic, generated exchange, mesh-output, or convergence-sensitive operation across the barrier. Disjoint writes additionally need a proof that another invocation or external observer cannot read them during the phase. An empty LDS declaration, wave size, a scalar condition, and the existing `writes_uavs` heuristic are each insufficient. A branch value uniform only per console wave can differ across the workgroup. One covering post-dominator can prove an unconditional join in a local region, but dynamic barrier counts still need proof across loop exits and early termination. [AMD RDNA2 §4.3 Workgroups and §4.4 dependencies](https://www.amd.com/content/dam/amd/en/documents/radeon-tech-docs/instruction-set-architectures/rdna2-shader-instruction-set-architecture.pdf)

The larger transformation has active overlap. [#192](https://github.com/Marvisak/VIctory/pull/192) analyzes uniform placement and LDS RAW/WAR at `4a365e3a`. [#1433](https://github.com/Marvisak/VIctory/pull/1433) models console-wave arrival and early termination through an explicit rendezvous schedule at `b3efa1c0`. Those approaches can handle effects beyond the narrow no-dependency case. Their eligibility and validation remain specific to their own implementations.
