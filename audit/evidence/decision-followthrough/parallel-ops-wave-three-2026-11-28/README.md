## Discovery before and after

The case was Xbox2Windows #3196, where a graphics command allocator must not be reset before the work that used it has completed. The [D3D12 Reset contract](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-id3d12commandallocator-reset) requires the waiting condition. The receiving presenter waits for its own fence. XCL #3062 holds and replaces a sparse allocator/list pair if necessary. Vice-Tay #144 recycles at landing after completion and separately retires resources. The RX 6700 XT reset in #144 remains open.

In the pinned seven-record replay, the baseline yielded zero. The new matcher yielded both target leads and excluded all four topical negative controls in both title and title+body replays. The live result's first two slots were Vice-Tay #144 and XCL #3062. Its remaining three links are broader identifiers, not verified fixes. This is a narrow, selected regression case rather than a general precision/recall estimate. [Product PR #144](https://github.com/akimfomin/PortBridge/pull/144) · [main commit](https://github.com/akimfomin/PortBridge/commit/6d1ed27a1dc083536c1404609deb83f241cb5b65) · [successful Pages push workflow](https://github.com/akimfomin/PortBridge/actions/runs/46092649170).

Use the exact GitHub revisions in [git-results.json](git-results.json). For one prospective pair, fetch the two PR refs at the recorded revisions and use `git merge-tree --write-tree <target> <head>`. A changed public PR ref is a new trial. Do not silently substitute it for the recorded head.

Run `python -I replay_discovery.py <PortBridge checkout>` first on `e2847c438af3377ab04fd20ee3ed4250b1a537c1` then `6d1ed27a1dc083536c1404609deb83f241cb5b65`. The [inputs](discovery-input.json) contain the public titles and short summaries. [Before and after](discovery-replay.json) includes the normal live URL result. To repeat the live test run `python -m portbridge.preflight --url https://github.com/R0Y00/Xbox2Windows/pull/3196 --limit 5`.

Use `python -m unittest discover -s tests` on the product revision. The normal export and `python -m portbridge.release_gate <site-dir>` passed. [Standalone commands, public source pins, hashes and receipts](cpu-receipts.md).

## Next round started

VIctory-RDNA #4 and KLBF #57 skip stale transfer work at different stages. [Returned a reproducible source-level check](https://github.com/XaviFortes/VIctory-RDNA/pull/4#issuecomment-7231768185): the byte-range predicate in the pinned VIctory-RDNA source agreed with explicit sets on 10,000 deterministic inputs around a page boundary. This does not measure D3D12 or hardware improvement. Keep byte-invalidating behavior within a page separate from deciding which pages to copy. The proposed shared test needs an accepted readback fixture and a separate control for aliasing, before any performance claim.
