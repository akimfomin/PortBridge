- В PortBridge #154 исправлены восемь отдельных проявлений: пропавший результат Lab в сводке Action, отсутствующая ссылка на точную ревизию, скрытая отметка о неполном поиске, неверное восстановление после повреждения начального манифеста, скрытая недоступность индекса исходников, устаревшие данные при повторном чтении, прежнее имя репозитория в точных источниках Radar и неверное наследование отзывов от родительского PR. Прошли 333 теста и проверка экспорта. GitHub Pages завершился успешно на `a46a25d03798dc3b1251b9619f9885bca1dac812`. Публичный рабочий маршрут FrameLab отдал два проверенных отчёта с точными ссылками. [PR #154](https://github.com/akimfomin/PortBridge/pull/154) · [Выпуск](https://github.com/akimfomin/PortBridge/actions/runs/46098028919)
- #156 добавляет поиск по полному SHA в локальном каталоге, публичном индексе, preflight и разделе Sources. Проверены PR с сохранённым SHA, старая ссылка на коммит без поля SHA, совпадение только по тексту, ложный путь и отсутствующая ревизия. Браузерный скрипт прошёл проверку синтаксиса, все 335 тестов и этап проверки экспорта прошли локально. Код на `main` равен протестированной версии. GitHub Pages завершил выпуск. Публичный запрос `e8f31c207199f546f4d8dbb6d33175e4b8d0949f` вернул Xbox2Windows #866 с тем же SHA. Для `ffffffffffffffffffffffffffffffffffffffff` выдано явное сообщение об отсутствии сохранённой ревизии. [Положительный пример](https://github.com/R0Y00/Xbox2Windows/pull/866). [PR #156](https://github.com/akimfomin/PortBridge/pull/156) · [main](https://github.com/akimfomin/PortBridge/commit/1bf55cc3a937205f43d90b2edde1be27558f2c82) · [Запуск GitHub Pages](https://github.com/akimfomin/PortBridge/actions/runs/46098762370)
- Оба внешних патча доступны в [описании](README.md). Для Xbox2Windows `git apply --check` и 340 проверок исходной CPU-модели прошли и на `8027ad6e7012ecd821ed7606ec86bcb6f227ca1d`, и на `eceb81af87456a1e887738c78c1ceee05c8d02f5`. После отказа автора патч хранится как узкий контроль. Полное сканирование внутренних интервалов между конечными ненулевыми результатами охватило 39 425 кодов. В пределах 0,5, 2, 4 и 8 шагов FP32 от середины оказалось соответственно 4, 10, 26 и 70 входов. При промежуточном округлении до ближайшего FP32 отличие от прямого округления до FP16 составило один случай: `0x11c5` дал `0x3c00` вместо `0x3c01`. Эта CPU-проверка не измеряет погрешность GPU. [Независимый расчёт](verify_exp2.py) · [Ответ автора](https://github.com/R0Y00/Xbox2Windows/pull/3220#issuecomment-7232409263)
- AnyXboxX, `512099cd752c7c07a19b60667a460af602b547e8`: чистое применение, ошибка на исходной версии, ожидаемый cache miss после изменения. Тест внедрил `PermissionError` в файловую операцию. Затем проверка с настоящим файловым дескриптором Windows дала `WinError 32` на исходной версии и cache miss на исправленной. Пока дескриптор открыт, байты на диске не меняются и результат не попадает в память. После закрытия дескриптора обе версии удаляют испорченную запись. Полный набор тестов AnyXboxX остаётся открытым. [Проверка Win32](verify_cache_win32.py) · [Правила совместного доступа Win32](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew) [Регрессия](verify_cache.py) · [Доставка](https://github.com/LooperSalty/AnyXboxX/pull/556#issuecomment-7232331916)

## Физические проверки, сотрудничество и эксплуатация

Новых независимых аппаратных результатов этой итерации нет. Открыта одна задача на физический D3D12-адаптер. Её получил один доброволец, у которого уже был публичный опыт проверки того же транслятора на AMD. Результат пока не поступил. Старые собственные прогоны авторов, новые CPU-тесты и WARP учтены отдельно. [Lab #155](https://github.com/akimfomin/PortBridge/issues/155) · [Приглашение](https://github.com/akimfomin/PortBridge/issues/155#issuecomment-7232373545)

Одно подтверждённое новое применение предложенного контроля получено от Continued. В KytyPS5 поступила проверенная на CPU реализация. Решения KytyPS5 пока нет. Согласованное подключение агентов трёх команд не подтверждено. Команда `python -m portbridge.network --outcomes-only` по-прежнему показывает ноль команд с подтверждённым повторным техническим использованием в новом пилоте. Исторический повтор FrameLab отображается отдельно.

Успешные облачные запуски по расписанию видны с предыдущим разрывом больше 7 часов, при расписании два раза в час. Среди шести последних проверенных запусков есть один неуспешный. Недельная автономность и соблюдение целевого интервала остаются открыты. [Успешный запуск](https://github.com/akimfomin/PortBridge/actions/runs/46095541312) · [Предыдущий](https://github.com/akimfomin/PortBridge/actions/runs/46052874542) · [Сбой](https://github.com/akimfomin/PortBridge/actions/runs/45761703311)

Из новых задач XCL уже указал на происхождение обработки исключения при сборке графического конвейера из victory-fork. Предел времени ожидания при продолжающейся сборке в victory-fork и ошибка инициализации работника в VIctory требуют других проверок. Общий симптом не делает эти исправления взаимозаменяемыми. PortBridge не засчитывает известный перенос. [XCL #3028](https://github.com/xcl-dev/xcl/pull/3028) · [victory-fork #1450](https://github.com/fxceless/victory-fork/pull/1450) · [VIctory #3636](https://github.com/Marvisak/VIctory/pull/3636)

## Воспроизведение PortBridge

```powershell
git switch --detach 1bf55cc3a937205f43d90b2edde1be27558f2c82
python -m unittest discover -s tests
node --check portbridge/static/app.js
python -m portbridge export --out dist-acceptance --repository akimfomin/PortBridge
python -m portbridge.release_gate dist-acceptance
python -m portbridge.preflight --url "https://github.com/5headsmartbtw/leonida-framelab/issues/15"
python -m portbridge.preflight --q e8f31c207199f546f4d8dbb6d33175e4b8d0949f
python -m portbridge.network --outcomes-only
```

Для повторения численного контроля достаточно стандартного Python 3. `python verify_exp2.py` запускается в этой папке. Для внешних патчей применяйте указанные в [описании](README.md) ревизии.
