# PortBridge · самостоятельный вход и применение

## Что опубликовано

[PR #157](https://github.com/akimfomin/PortBridge/pull/157) добавляет отдельный GitHub issue для каждого технического вопроса. Раньше README направлял новые запросы в одну общую тему. Форме нужны публичный PR и вопрос, а точная целевая версия нужна для проверки переноса. Обращение добровольное, у темы нет гарантированного срока ответа. Старые обсуждения по-прежнему открываются. Новая форма также указана в прежней теме #98. [Объявление](https://github.com/akimfomin/PortBridge/issues/98#issuecomment-7232741647) [Форма](https://github.com/akimfomin/PortBridge/issues/new?template=pr-check.yml) · [Источник формы](https://github.com/akimfomin/PortBridge/blob/3a39218809d05a696a6154eb761111ce5a1bbfa8/.github/ISSUE_TEMPLATE/pr-check.yml)

Раньше задача Xbox2Windows #155 была только выдаваемым вручную issue, а не частью Lab. Задание добавлено в экспорт, фильтры и существующий приём отчётов на AMD, Intel и NVIDIA. Критерии фиксируют точный коммит, физический адаптер и отдельный статус каждого из четырёх входов. Изолированный пакет прошёл 335 тестов и проверку экспорта. Дополнительный запуск проверил все семь сценариев приёма отчётов. Маршрут MCP вернул тот же закреплённый тест по каждому из трёх GPU-фильтров, фильтр CPU выдал пустой список. Опубликованный JSON дал точный тест, ревизию, четыре входа и ссылку на #155. ## Внешние результаты

1. **Xbox2Windows #3220.** R0Y00 сам прогнал 12 сценариев в Debug и Release без пропусков на RTX 4060 Laptop. Точная совмещённая версия `855194f4c009c36a64ea032d557e367b056e47f5`, Windows 11 26200.9974, драйвер 32.0.16.1656. Это один независимый от автора PR аппаратный отчёт. Он проверил существующий набор с допуском и вспомогательные тесты FMA. Для FP16 сопровождающий отдельно выбрал поправку с доказуемой границей ошибки, точные пограничные GPU-проверки и отклонение операции при отсутствии гарантии. Это принятое техническое решение, а реализация остаётся в работе. [Отчёт и решение](https://github.com/R0Y00/Xbox2Windows/pull/3220#issuecomment-7232513116) · [Задание Lab](https://github.com/akimfomin/PortBridge/issues/155)

2. **Vice-Tay #392.** Urielbeaupre сравнил PR и неизменённый main после переданного вопроса. Нестабильный тест падает на обеих версиях, 1/15 против 3/15. Из этих результатов нельзя заключить, что частота ошибок одинакова. Это CPU-проверка, открытый PR ещё не принят. [Ответ автора](https://github.com/TaynanGT/Vice-Tay/pull/392#issuecomment-7232285516)

3. **AnyXboxX #575 и victory-fork #1442.** Публичный файл `third_party/victory/crates/victory-gpu/src/pipeline/library.rs` совпадает на `132da61504cc2c2d086796c468a8ace1759aba22` и `c1ba64581b14885c4c565ec239bed149dd7677a9`. Оба дали SHA-256 `0811947573af8283114b42da18b58f6374d8dbce221f50e62a1a030d5c9ae3d7`. Для строк `00000000000000000000000000000000` и `00000000000000000000000000000022` расчёт `(hash * 31 + byte) % 64` из исходника дал слот 0. Отдельные имена могут ждать один замок. Предложенный тест проверяет раздельное ожидание разных имён и последовательное исполнение для одинаковых. Уже измеренные задержки принадлежат автору victory-fork. Связь с зависанием трансляции AnyXboxX не установлена. [Старый механизм](https://github.com/LooperSalty/AnyXboxX/blob/c1ba64581b14885c4c565ec239bed149dd7677a9/third_party/victory/crates/victory-gpu/src/pipeline/library.rs#L424-L431) · [Тест victory-fork](https://github.com/fxceless/victory-fork/blob/c13e2a390930cacfa68fb27a3341445b18c71c2e/crates/victory-gpu/src/pipeline/library.rs#L756-L789) · [Передача](https://github.com/LooperSalty/AnyXboxX/pull/575#issuecomment-7232661796)

4. **Входящие заявки и рекомендации.** В новой волне нет подтверждённых самостоятельных запросов, новых подключений или повторного использования. Выступление или размещение новой ссылки в этот раз не подтверждено. Ранее опубликованная рекомендация Awesome подтверждена автором каталога. PC Race отказался, PortWatch не ответил на существующее предложение. У ссылки Six on PC при повторной проверке HTTP 404; прошлое размещение сохраняется в истории. ## Готовый тест FP16 для второго стенда

[Поправка к синтетическому тесту](exp2-exact-output.patch) добавляет четыре точных входа и два соседних контроля. Она пишет фактическое 32-разрядное слово и эталон для каждой группы и формы инструкции. Транслятор и его прежний допуск эта поправка не меняет. В отчёт включите строки `exp2 group=` и точные данные стенда. В исходном тесте код выхода 77 означает отсутствие Wave32 и не засчитывается как аппаратная проверка.

```powershell
git switch --detach eceb81af87456a1e887738c78c1ceee05c8d02f5
git apply --check <path-to-exp2-exact-output.patch>
git apply <path-to-exp2-exact-output.patch>
python tests/native_f16_alu_check.py model
ctest --test-dir <build-directory> --no-tests=error --output-on-failure -V -R "^native_f16_alu_hardware$"
```

Локально проверены применимость и 344 значения CPU-модели, включая два негативных контроля. Новые точные аппаратные значения ещё не получены.

## Приёмка NET-05

В публичных обсуждениях проверены шесть отдельных адресных предложений. Они охватывают руководителя Vice-Tay, разработчиков и сопровождающих AnyXboxX, XCL и victory-fork, тестировщика KLBF и участника PortWatch. У каждого предложения был один конкретный следующий шаг, основанный на исходных данных.

| Работа | Следующее действие из обращения |
| --- | --- |
| [Vice-Tay #273](https://github.com/TaynanGT/Vice-Tay/issues/273#issuecomment-7230521445) | Передать один свободный PR и решение для проверки без установки. |
| [AnyXboxX #436](https://github.com/LooperSalty/AnyXboxX/pull/436#issuecomment-7205213561) | Сохранить проверенный тест перекрывающихся readback при переносе в Vice-Tay. |
| [XCL #2910](https://github.com/xcl-dev/xcl/pull/2910#issuecomment-7205205815) | Прогнать парный контроль сбора кэша при включённой и выключенной записи. |
| [victory-fork #1414](https://github.com/fxceless/victory-fork/pull/1414#issuecomment-7206317317) | Проверить границу 240/241 в двух новых процессах с режимами OFF и ON. |

По итогам ответов и проверок подход уточнён: новый вход хранит каждый вопрос в отдельном issue, лабораторное задание хранит точный тест, а подтверждение команды учитывается отдельно. Это закрывает стартовую волну NET-05. Подключения, повторное использование, внешнее размещение и завершение всей цепочки Lab проверяются по отдельным требованиям. NET-09, NET-12, LAB-09, AG-07 и OPS-06 остаются в прежних состояниях. Публичный реестр содержит 82 verified, 39 partial и 1 blocked.
