## Reproduce

1. In a repository you control, copy [the example](../../../examples/portbridge-pr.yml) to `.github/workflows/portbridge-pr.yml` on its default branch. The example selects that repository, requests `permissions: {}`, has no checkout of PR code and has a two-minute timeout. GitHub routes authenticated PR events to its runner. PortBridge exposes no incoming webhook. For a manual-only subscription, remove the PR trigger. [Installation and rollback](../../../docs/GITHUB-ACTION.md)
2. Run the workflow from its form with the URL above. Open the Job Summary for the input revision, reviewed card and source. For an automatic event, open a normal PR and check the source URL and full event head against the revision on GitHub. Re-run the same job. Snapshot contents can legitimately change between runs.
3. To repeat the fault controls, use the pinned fixture workflow from the table in a disposable repository. The proxy is confined to one workflow step on its temporary runner. Other steps use the usual network. Disable the workflow and push a new commit to the open PR. GitHub's workflow metadata and the runs query for that SHA show whether the subscription was disabled.
4. From this checkout, run `python -B -m unittest discover -s tests -p test_action_summary.py -v`. Negative controls cover private, oversized and malformed events, missing head, inaccessible origin, safe rendering of PR text, missing summary destination and no-write outcomes.

The live snapshot used for the fixture reported stale/partial source coverage. The UI displayed this on both attempts. The results measure transport, visibility and failure handling; the five prospective Discovery misses in [M5.3](../m53/assessment.md) remain open.
